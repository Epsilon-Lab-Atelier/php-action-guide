# 確認の続きと共有リンク

## 確認途中の状態

ページを開いている間は、サービスと立場の組み合わせごとに、使い方・情報流出の条件・確認済みチェックをメモリ内に保持します。同じサービスを押し直しても消えず、別のサービスへ移って戻ると復元します。利用者向けと管理者向けのチェックは別々です。テーマ切替でも保持します。

「確認をやり直す」から確認画面を開くと、現在のサービス・立場のPHPと情報流出のチェックだけを解除できます。使い方や条件の選択、他のサービスのチェックは維持します。取消とEscapeキーでも戻れます。

再読み込みでページ内の状態はリセットします。未登録・不正URLの状態を、登録サービスの記録に混ぜません。入力URLやドメインをサービス別の保存記録へ入れません。後から見返す確認内容は、従来どおりメモのコピー・テキスト保存・印刷で残せます。

## サービス別リンク

案内の「この案内へのリンクをコピー」で、サービス・立場・テーマだけを含む公開版へのリンクを作れます。自動コピーが使えない場合は、読み取り専用の手動コピー欄を表示します。

| 用途 | 公開版URLの末尾 |
| --- | --- |
| noteの情報流出の案内 | `#service=note&role=user&topic=breach` |
| 自分で設置するWordPressのPHP案内 | `#service=wordpress-selfhost&role=admin&topic=php` |
| PHPのテーマだけを開く | `#php` |
| 情報流出のテーマだけを開く | `#breaches` |

サービスを指定する場合は `service`・`role`・`topic` の3項目を指定します。サービスIDは登録済みのもの、立場はそのサービスに対応する `user` / `admin`、テーマは `all` / `php` / `breach` です。不正値・重複項目・未知の項目・不正なエンコードは無視し、違うサービスの案内として補正しません。

リンクには入力URL、利用状況、購入や支払いの選択、確認済みチェックを含めません。現在のページのクエリ文字列もコピーしません。公開先を変更するときは、`src/app.mjs` の `publicGuideUrl` を実際の配信先へ変更してください。

フッターには、EpsilonLabの公開済みPHP解説記事へのリンクと、この手帳の説明へのページ内リンクを設けています。手帳の紹介記事のURLは未設定です。別の記事を追加する場合も、公開済みの正確なURLを確認して設定してください。

## 希望したサービスだけ端末に保存

「このサービスを端末に覚えておく」を押したときだけ、次の情報をlocalStorageへ保存します。

- 登録済みサービスのID
- 利用者 / 管理者の立場
- 公開された掲載内容から計算した、変更を見分けるための目印

チェック・利用状況・入力URL・テーマ・個人情報は保存しません。保存一覧の読み込みだけでは書き込みません。保存が拒否された場合や容量不足の場合は理由を案内し、通常の確認やメモ保存は引き続き使えます。

保存したサービスは「いつものサービス」から開けます。掲載内容が保存時から変わった場合は、案内を読み直す表示を出します。「掲載内容の変更を確認した」を押すと目印を更新します。これは安全性や修正完了の判定ではありません。確認済みチェック自体は永続保存しないため、再訪時に以前のチェックを完了扱いにしません。

目印は公開内容の違いだけを見るもので、端末を識別する値ではありません。資料の確認日だけが変わった場合は更新扱いにしません。事案や公式案内などの同日中の内容変更は区別できます。

サービスごとの解除と、保存一覧の全削除を用意しています。削除するキーは `epsilon-service-notebook.saved-services.v1` だけです。他のアプリの保存内容は消しません。壊れたデータを読み込んでも、自動で修復・上書きせず、明示的な削除を案内します。

## 情報流出のカード

対象範囲、利用・登録などの対象期間、公式に案内されていることを、カード上で続けて表示します。対象期間を読むための展開操作は不要です。情報の種類・発生時期・事業者の対応・資料の日付は詳細欄に残しています。公式資料から確認した対象条件の省略や変更は行っていません。

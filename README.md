# ネットサービスの確認手帳

EpsilonLabによる、PHPの問題と情報流出・不正アクセスについて、公式情報と自分に必要な確認事項を整理する日本語Webアプリです。利用者とサイト管理者の立場を分け、事案の対象範囲、判明していること、公式の対応案内を記録します。旧名称はPHP Action Guideです。

## 使う

`dist/index.html` をブラウザで開いてください。HTMLにCSS、JavaScript、登録情報を含むため、サーバーの起動やインストールは不要です。公式資料への移動にはインターネット接続が必要です。

- 利用者・管理者の立場を選び、一覧からサービス・CMS・サーバーを選ぶか、URLを入力します。
- 一覧は立場ごとに異なります。名前・読み・登録ドメインで入力中に検索でき、用途のカテゴリでも絞り込めます。
- URLは登録ドメインとだけ照合します。URL先への通信、DNS照会、PHPの検査は行いません。
- `amazon` のような名前は一覧の名前検索に、`amazon.co.jp` のようなドメインはURL検索に入力します。
- 独自ドメインなどで一致しなければ、利用先を確認して一覧から選んでください。
- 未確認の内容から、安全・対応不要・PHP不使用とは判断しません。

v0.6.0の掲載対象は重複を除いて22件です。利用者向け14件、管理者向け13件で、一部の項目は両方の立場に掲載しています。PHP資料の情報確認日は2026-10-24です。情報流出等は7件の記録（さくらの2つの影響範囲を分離）を9件の公式資料に基づいて追加しました。確認日は各資料に記載します。

| 立場 | 用途 | 掲載対象 |
| --- | --- | --- |
| 利用者 | 買い物・フリマ | BOOTH、Amazon.co.jp、楽天市場、Yahoo!ショッピング、メルカリ、BASE |
| 利用者 | ブログ・投稿サービス | note、WordPress.com |

| 管理者 | 自分で設置するCMS | WordPress、Drupal、EC-CUBE |
| 管理者 | レンタルサーバー | さくらのレンタルサーバ、エックスサーバー、ロリポップ!、ConoHa WING |

## テーマと事案を選ぶ

「すべて」「情報流出・不正アクセス」「PHPの問題」を切り替えられます。`#php` / `#breaches` 付きのURLは該当テーマから開きます。サービス一覧と使い方の選択は共通です。テーマを変えても同じサービスのチェックは保ちます。

情報流出の各記録は、初公表日・続報日・対象範囲・対象期間・情報の種類・公式の対応案内・資料確認日・掲載変更日を持ちます。流出の確認、可能性、不正アクセスの確認は区別し、事業者の対策完了から「流出していない」とは判断しません。以前の利用・退会、住所登録、支払い、個別通知に合わせて一般的な確認手順を追加できます。購入・支援の選択も支払いの確認手順へ反映します。

記録がないサービスも表示しますが、未掲載は被害なしを意味しません。関連会社・委託先・限定機能の範囲を親サービス全体へ広げず、過去の事案には公表年を明示します。初回調査の範囲と掲載判断は `docs/incident-research.md` を参照してください。

## 使い方に合わせた確認メモ

サービスを選んだ後、そのサービスに合わせた使い方を複数選択できます。登録・閲覧・購入・出品販売・投稿を基本に、LINEではメッセージ、買い物サイトではレビューなど、選択肢と一般的な確認手順を調整します。未選択でも公式案内を確認できます。選択に合わせて一般的な確認メモと確認数を表示します。これは危険度や被害の診断ではありません。各サービスの公式な対応指示とは別に表示します。

選択・チェックは自動保存も外部送信もせず、サービスや立場を変更するとリセットします。テーマだけの切替では保持します。必要な場合はメモをコピー・テキスト保存・印刷できます。配色は白に近い生成りの紙面・薄い桜色を中心に、淡い若草色を添えています。文字は濃紺と落ち着いたローズ色を使い、淡色のボタンでも読みやすくしています。0.4.1では「自分の確認メモをつくる」紙・手帳風のデザインを明確にし、紙面の影、余白の罫線、しおり、テープ風の小さな装飾を用いています。主見出しは明朝体、本文と操作部分はゴシック体です。

## メモを手元に残す

結果の「確認メモを、手元に。」から、表示中のテーマの対象事案、サービス、立場、選んだ使い方、確認済み項目、公式説明、根拠リンク、確認日と変更日を出力できます。複数事案は分けて記載し、選択サービスに関係する出典だけを含めます。

- コピー: 端末のクリップボードへコピーします。利用できない画面では全文を選択した手動コピー欄へ案内します。
- テキスト保存: UTF-8の `.txt` ファイルを端末へ保存します。保存が制限されるプレビューでは、手動コピー欄を使います。
- 印刷 / PDF: ブラウザの印刷機能を開きます。PDF保存の選択肢は使用する端末・ブラウザによります。
- 内容を見る: 保存前にメモを確認でき、チェック操作をすると表示内容も更新されます。

保存メモは作成時点の写しです。自動更新されません。入力URLのパス・クエリ・フラグメントは含めず、照合したドメインだけを記載します。

## 更新内容を確認する

結果に資料の確認日（参照資料のうち最も古い日）と、掲載内容の最終変更日を分けて表示します。出典別の確認日も確認できます。「このサービスの掲載情報の履歴」で変更を確認し、ページ下部の「このガイドの更新メモ」では日付を指定して、その日より後の内容変更を絞り込めます。

記録開始は2026-10-24です。記録開始以前の変更日は推測しません。初回の記録とアプリの機能・デザイン更新は、サービスの対応状況の変化とは区別します。

## 開発

Node.js 22以上を使用します。外部パッケージのインストールは不要です。

```sh
npm run build
npm test
```

ビルド後の `dist/index.html` は単一ファイルです。相対パスに依存する外部アセットがないため、GitHub Pagesのプロジェクトサブパスでも使えます。

## 情報を更新する

公式の一次情報を読み、`src/catalog.mjs` または対象の分割カタログの事実・出典・確認日を更新します。追加項目には掲載する立場、立場ごとの用途、検索用の読みも設定します。公式窓口のリンクを追加しただけで、PHPの利用・修正済みなどの根拠にはしません。全体の確認日を更新するときは `src/index.html` にある日付と対象問題の説明も見直します。`npm run build` と `npm test` を実行し、ブラウザで表示を確認してください。

日付だけを新しくせず、実際に確認した資料の範囲を記録してください。古い告知から、新しい脆弱性への対応済みとは推測しません。確認日から7日以上が経過すると、公式情報の再確認を促す表示が出ます。

定期調査の開始条件と差分更新の方針は `docs/automatic-updates.md`、開始・停止の設定は `maintenance/policy.json` に記載しています。開始条件は、`maintenance/policy.json` の設定を含む初回pushです。Webサイトの公開とは独立しています。毎朝のタスクは両テーマを調査してレビュー用PRまで更新し、自動マージやデプロイは行いません。

## GitHub Pagesへの準備

公開時は、承認したコミットの `dist/` の内容をPagesの配信ルートへ置きます。ブランチ配信を使う場合は、配信用ブランチのルートへ `index.html` と `.nojekyll` を配置できます。これは公開作業の説明であり、このソース一式に自動デプロイする設定やActionsは含まれていません。

現時点で公開サイトは提供していません。GitHub Pagesの公開範囲や設定の変更は、公開時に別途行ってください。

## 制約

登録情報は手作業で確認した時点の記録です。最新情報の自動取得、任意サイトのPHP検査、被害判定、脆弱性スキャン、リアルタイムの稼働監視はありません。個別サイトや未登録ドメインの状態は判定できません。

入力やチェック状態をアプリ側で自動保存・外部送信しません。メモは明示的な操作で端末へ保存・コピーできます。ブラウザの復元機能などで画面が残る場合があります。公式リンクは新しいタブで開き、参照元を送らない設定にしています。

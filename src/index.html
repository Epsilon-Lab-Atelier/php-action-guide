このリスクチェックについて

情報漏洩・不正アクセスとPHPの問題を分け、公式発表の対象範囲と対応案内を掲載しています。利用状況を選ぶことで、関係する確認事項を絞り込めます。

個人の被害や安全性を判定するものではありません。メールアドレスやパスワードの入力は不要です。最新の状況と個別の対象判定は、リンク先の公式案内で確認してください。

PHP問題の概要

2026年10月に公表された、PHP2Shellと呼ばれる問題を中心に扱っています。PHPは、Webサイトの裏側の処理を動かすために使われる言語です。

対象の問題・影響条件・管理者向け情報を見る

10月21日に修正版が公開された2件

CVE-2026-109618 / CVE-2026-109619

PHP内部のメモリや状態の扱いに関する問題です。条件がそろうと、ログインしていない第三者がサーバーに不正な処理をさせるおそれがあります。PHP公式は、Webからのリクエストを処理するPHP環境に更新を呼びかけています。Windowsや特定のCMSだけの問題ではありません。

この2件の修正を含むリリースは 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12 です。配布元が修正を取り込む場合もあるため、表示バージョンだけで判断せず配布元の案内を確認してください。CMS本体やプラグインの更新だけでは、PHP自体の修正を確認したことにはなりません。

10月21日の2件は、修正を含むリリースへの更新が完全な対策です。設定変更などの暫定策だけで、すべての攻撃経路への対策が完了したとは判断しません。

10月23日の追加案内も確認してください

CVE-2026-115560 は別の追加案内です。アップロード進捗機能が有効で、session.serialize_handler を設定で php_binary または php_serialize にし、実行時に ini_set() で php へ変更してから session_start() を呼ぶ特殊な組合せが条件とされています。

上記4つの修正版に更新済みでも、この追加案内の条件は別に確認してください。PHP公式は次の通常修正版まで session.upload_progress.enabled=0 を推奨しています。既に無効化している場合は設定を維持すれば追加作業は不要と説明しています。実行時にハンドラーを変更しないアプリは、この機能を維持できます。設定を変更する管理者は、提供元の手順に沿って全PHPワーカーへの反映も確認してください。

このガイドの情報・URL検索について

公式ページの本文を確認した情報を掲載しています。各サービスの説明は、その資料が対象にしているサービス・問題・時点の範囲に限ります。最新状況はリンク先を確認してください。

「未確認」は掲載資料から判断できない状態、「掲載情報なし」は登録情報がない状態です。公式発表が世界中のどこにも存在しないという意味ではありません。

URL検索は登録ドメインとの照合だけです。PHPの利用状況、バージョン、修正適用、情報流出は検査しません。登録済みサービスでも、独自ドメインや登録外のサブドメインは一致しません。

ウォッチリストの企業・サービスと、前回開いた掲載内容の識別情報だけをこのブラウザに保存します。端末間の同期はありません。利用状況の選択は、このページを開いている間だけ保持します。入力したURLや選択内容は外部に送信せず、端末への自動保存も行いません。公式リンクを開くと、その公式サイトへ移動します。

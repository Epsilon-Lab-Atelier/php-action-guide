# 設計と情報の取り扱い

## 利用の流れ

v0.10.0の名称は「ネットサービスのリスクチェック」です。「サービスの公開情報 → 利用状況の選択 → 関係する情報と対応」という流れに絞ります。チェック済みの記録とメモ作成・コピー・保存・印刷は設けません。気になる企業はウォッチリストにまとめて確認できます。旧版の保存領域にはアクセスしません。

公開情報は常に表示し、選択によって事案自体の状況を書き換えません。利用状況を選ぶと `risk-guidance.mjs` が公表資料に基づく対象範囲と、条件付きの案内を返します。該当性を断定せず、利用頻度・選択数・チェック数による点数や危険度は生成しません。一般的な対処と公式に案内された手続きは区別します。PHPと情報漏洩はそれぞれ独立して扱います。

## データと根拠

PHPカタログは `catalog.mjs` とその分割ファイル、情報漏洩は `incidents.mjs` と `catalog-breach.mjs` で管理します。`service-directory.mjs` は検索用に結びますが、情報漏洩専用の企業にPHPの情報を補いません。出典はHTTPS URL、公表日、確認日、必要に応じた確認方法の注記を持ちます。

PHPの使用、脆弱性の影響条件、修正適用、被害確認は別の事実です。情報漏洩の確認、可能性、調査中、漏洩を否定する続報も区別します。修正・再発防止が完了しても、既に情報が流出したかどうかの結論にはしません。公式窓口リンクは対応済みの根拠には使いません。

## 利用状況に応じた表示

`riskOptionsForService` はテーマ・立場と掲載情報に合う選択肢を返します。選択内容から公表されていない被害や原因を推定しません。複数事案がある場合は事案ごとの状態を保持し、古い事案を最新の状況に混ぜません。閲覧したという選択だけで登録情報の流出対象とは判断しません。退会済みという選択だけでも対象外とは判断しません。

PHPの管理者向けは環境・対応状況を選び、契約先への確認と自主管理環境で行う作業を区別します。サービス利用者にサーバーの設定変更を案内しません。

## 更新履歴

更新履歴はチェック画面と別の画面に集約します。`update-view.mjs` が変更日ごと、企業・サービスごとにまとめ、重複する事案を1社として数えます。テーマ・企業名の絞り込みと、当日の更新の有無を表示します。時刻の境界は日本時間で計算します。最初の記録起点、掲載追加、続報・訂正、アプリのリリースは区別します。

公式資料を読んだ日は出典の確認日、アプリに掲載した説明が変わった日は掲載変更日です。デザイン変更で資料確認日を進めたり、実際にはない企業の続報を作ったりしません。

## 検索とURL照合

名前の検索ではNFKC、英字の小文字化、カタカナからひらがなへの変換で表記をそろえ、空白区切りの複数語をすべて含む項目を返します。サービス名・説明・キーワード・登録ドメインに加え、記録された運営企業名（`operator`）と企業名の別表記（`companyAliases`）を検索します。運営企業名や別表記は公式資料で確認できたサービスに限って追加し、企業グループ全体へ事案を広げません。

「サービスの種類」は常に見えるネイティブのプルダウンで、検索語と組み合わせて絞り込みます。別テーマだけに掲載されたサービスが検索語と一致した場合は、テーマと立場を明示した移動操作を用意します。移動時は検索語を維持し、種類を「すべて」に戻します。情報漏洩の掲載からPHPの利用・影響・原因を推測しません。

URLは標準URLパーサーでホスト名だけを取り出し、明示された登録ドメインの完全一致または許可されたサブドメインで照合します。ユーザー情報、非HTTPスキーム、IPアドレスやローカルドメインなどは受け付けません。パスやクエリを結果に残さず、入力先への通信・DNS照会は行いません。CMSやサーバー事業者の公式サイトから、利用者自身の環境を推測しません。

以前のサービス別リンクは読み込み互換を保ちます。リンクに利用状況や入力URLを含めません。

## 画面と実装

白と淡いグレーを土台に、ネイビーの文字とブルーの操作色を使います。見出しは小さく明確にし、装飾よりも検索・結果・次の行動を優先します。デスクトップでは検索列と結果を分け、モバイルでは縦に配置します。キーボードフォーカス、選択状態、折りたたみ状態を示します。色だけで状況を伝えません。

外部依存のないHTML/CSS/JavaScriptを一つのHTMLへビルドします。CSPはバンドルと一致するハッシュを生成し、`connect-src 'none'` により実行時の外部通信を制限します。入力は `textContent` で表示し、HTMLとして挿入しません。外部フォント、解析タグ、Cookie、Service Workerは使いません。ウォッチリストの企業IDとテーマ別の閲覧内容の識別子だけをlocalStorageに保存し、利用状況や入力URLは保存しません。ブランド画像は既存のEpsilonLab画像を埋め込みます。

## ウォッチリストと確認日時

`watchlist.mjs` は読者が追加した企業・サービスと、テーマ別に前回開いた掲載内容の識別子を保持します。情報漏洩とPHPの一方を開いても、他方の変更表示は消しません。識別子は内容差分用で、端末識別や個人の被害判定には使いません。確認日時だけの更新では変更表示を出さず、同日中の実質変更は区別します。旧メモ保存領域は読み込みません。

`information-status.mjs` は参照資料のうち最も古い成功確認日時を表示し、部分的な再確認を全資料の更新と見せません。日付だけの旧記録に時刻を補いません。掲載変更日時と、明示的に比較した対応案内の変更日時は独立しています。

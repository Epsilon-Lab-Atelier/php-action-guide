# ネットサービスのリスクチェック

使っているサービスの公式情報から、自分に関係する情報と必要な対応を確認するWebアプリです。情報漏洩・不正アクセスと、PHPの問題を分けて掲載しています。

## 使い方

1. テーマを選び、サービス名・企業名またはURLから探します。「サービスの種類」のプルダウンでも絞り込めます。
2. 公開されている状況、対象範囲、公式の対応案内を確認します。
3. 自分の利用状況を選ぶと、「まずすること」と関係する情報が表示されます。対象期間は詳細を開かずに確認できます。

検索したサービスが別のテーマに掲載されている場合は、検索語を保ったまま移動できます。「GMOインターネットグループ」など、記録された運営企業・グループ名から対象サービスを探すこともできます。

利用状況は、登録・支払い・本人確認書類の提出・過去の利用など、掲載されている情報の範囲に合わせて選べます。選択の数や利用頻度で危険度を採点せず、個人の被害の有無も判定しません。確認メモの作成・保存や、確認済み項目のチェックはありません。

## ウォッチリスト

サービスの案内で「＋ ウォッチリスト」を押すと、気になる企業をまとめて確認できます。情報漏洩とPHPの状況、掲載情報の変更日、前回案内を開いた後の内容変更を表示します。同じ日の更新も区別し、資料を再確認しただけでは新しい掲載変更として数えません。

ウォッチリストは、このブラウザに企業・サービスIDと、テーマ別に前回開いた内容の識別情報だけを保存します。他の端末とは同期しません。保存が使えない場合はページ内だけで利用でき、企業ごとに解除できます。

## 更新履歴

上部の「更新履歴」で、その日にどの企業・サービスの掲載情報が追加・変更されたか確認できます。日付、テーマ、企業名で絞り込み、変更内容と出典を確認して各サービスの案内へ進めます。初めて掲載した記録、続報・訂正、アプリの機能変更を区別しています。

公式資料の確認日時、掲載内容の変更日時、比較記録のある対応案内の変更日時を区別します。過去の資料で時刻が残っていない場合は「時刻未記録」と表示し、必要な対応の変更は、比較できた場合だけ明示します。

日付はこのアプリの掲載内容を変更した日です。事案の発生日、公式発表日、資料を読んだ日とは異なります。

## 調査と公開への反映

PHP対応は `src/catalog*.mjs`（`catalog-breach.mjs`を除く）、情報漏洩の事案は `src/incidents.mjs` に独立して記録します。PHPに掲載していない企業も `src/catalog-breach.mjs` に追加できます。情報漏洩からPHP利用や原因を推定しません。

外部の定期タスクは日本時間の毎日6時・18時に調査を開始する設定です。公式本文で確認できた情報を更新し、差分の点検・ビルド・テスト・PRのCIが通った内容をマージして、既存のGitHub Pagesへ反映します。時刻は調査の開始予定であり、公開完了時刻ではありません。確認日は実際に読めた資料だけ更新し、未確認情報や検証に失敗した更新は保留します。[定期調査の運用](docs/automatic-updates.md)に詳細を記載しています。

## 情報の扱い

利用状況の回答と入力URLは外部へ送信せず、端末にも保存しません。ウォッチリストだけを明示的な操作でこのブラウザに保存します。URL検索は登録済みドメインとの照合です。入力先への接続、PHPの検査、個別の被害確認は行いません。未掲載や未確認を「被害なし」「安全」と判断せず、公式の最新案内を確認してください。

# 公式情報の定期調査と差分更新

## 構成

GitHub Pagesは静的ファイルを配信します。公式情報の調査はアプリの外側で動く定期実行タスクが担当し、変更案をGitHubの作業ブランチとPull Requestにまとめます。アプリ本体から検索APIやAIへ接続することはありません。

定期実行の予定は日本時間の毎朝8時ごろです。実行予定と成否は定期実行タスク側で管理します。このリポジトリにファイルを置くだけでは、定期実行タスク自体は作成されません。

## 公開後の開始条件

`maintenance/policy.json` の初期値は待機状態です。公開リポジトリが存在するだけでは、更新を開始しません。

公開を依頼された際に、次をまとめて設定します。

1. ユーザーが指定した対象リポジトリと `repository` が一致することを確認し、`repositoryConfirmed` を `true` にする。
2. 公開サイトがこのアプリであることを確認し、実際のURLを `publishedSiteUrl` に記録する。
3. `enabled` を `true` にし、この設定を対象リポジトリの既定ブランチに反映する。
4. 定期実行タスクの対象が同じリポジトリであることを確認する。候補から変更した場合は、タスク側も同時に更新する。

開始条件が満たされるまでは、タスクは待機し、カタログの変更や公開作業を行いません。毎日の調査を個別に依頼する必要はありません。停止時は `enabled` を `false` にするか、定期実行タスクを停止します。

## 1回の調査

1. 認証アカウントが `Epsilon-Lab-Atelier` であることを確認する。別のアカウントへ切り替えない。
2. 既定ブランチの最新版と既存の更新用Pull Requestを読み、開始条件を確認する。
3. PHP公式の対象問題・追加案内と、掲載サービスの公式告知・ヘルプ・セキュリティ案内を調べる。既存URLの変更検出だけで終えず、新しい公式告知も探す。根拠未掲載の項目を優先する。
4. 公式ページの本文を読み、サービス・問題・影響条件・説明時点・利用者への指示を確認する。検索結果の見出しだけで断定しない。
5. PHPの利用、対象問題への対応、利用者の手続きを分けて記録する。公式窓口へのリンクだけでは、PHP使用や修正済みの根拠にしない。
6. 意味のある変更が確認できた場合に、対象のカタログ・出典・確認日を更新する。`npm run build` と `npm test` を実行し、生成HTMLも更新する。
7. 匿名性、差分、出典、検証結果を確認し、更新用ブランチ `maintenance/official-information` のPull Requestを作成または更新する。既存の未反映案と重複させず、無関係な変更は含めない。

## 日付・取得失敗・変更なし

- 公式ページを実際に読めた日を、出典の確認日として記録する。検索を試しただけの日や、取得に失敗した日で確認日を上書きしない。
- カタログ全体の確認日を更新するには、対象説明と掲載情報全体を再確認する。一部だけ確認できたときは、その出典の確認日だけを更新する。
- 取得失敗は対応状況の変化ではない。既存の根拠や説明を消さず、失敗した確認先を調査結果に残す。
- 変更がなければ、日付を進めるだけのPull Requestは作らない。調査の実行記録は定期実行タスク側に残し、通知を省く。
- 判断が分かれる内容は未確認のままにし、候補資料と判断できない点を更新案に記載する。
- 新たな利用者の対応指示、重要な変更、更新を妨げる取得・認証・検証の失敗は通知する。成功したように報告しない。

## 更新権限の範囲

自動更新は、調査・ファイル差分・レビュー用Pull Requestまでです。自動マージ、公開設定の変更、デプロイ、他のリポジトリへの書き込みは行いません。公開への反映は、別途依頼された公開手順に従います。

コミットの表示名には `Epsilon-Lab-Atelier`、メールには同アカウントのGitHub noreplyアドレスを使用します。本文・出典の要約・ログ・画像・履歴に、開発者個人を特定する情報や認証情報を含めません。

## 利用者向け案内の改善方針

技術情報が未確認でも、利用者が次に何を確認すればよいかは説明できます。「未確認」を繰り返す前に、公式のお知らせやアプリ内通知に自分向けの手続きがあるかを確認するよう案内します。サービス側のPHP更新と、一般利用者に求められる作業を区別します。

掲載項目は、対象問題の公式説明を掲載できた段階、関連告知との関係が未確認の段階、公式窓口を案内する段階を区別します。未掲載の資料を調べ、「公式発表がない」と「このガイドにまだ掲載していない」を混同しません。
